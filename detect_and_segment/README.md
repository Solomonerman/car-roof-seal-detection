# GAD 胶条检测 —— 在你自己电脑上跑

这个包里是一个已经训练好的检测模型 + 跑它的脚本。你把它指向自己的车身图片，
它会**自动找出深色胶条在哪，把胶条及其边界轮廓画在图上**，并给出一份几何数据（JSON）。

不需要 GPU，也不需要标注数据。全部在 CPU 上跑，实测**单张图约 0.3 秒**。

---

## 1. 装环境

需要 Python 3.10 以上。然后：

```bash
pip install -r requirements.txt
```

`requirements.txt` 里锁了 `ultralytics==8.4.129`——**这个版本号别动**。模型的行为跟
ultralytics 版本绑定，换版本结果会变，我们所有验收数据都是在这个版本上量的。

⚠️ **`torch` 和 `numpy` 必须配套**，这是最容易踩的一个坑：

| 你的 torch | 需要的 numpy |
|---|---|
| 2.1 这种老版本 | **必须 1.26**（numpy 2.x 会让它跑到一半才崩，报 `compiled using NumPy 1.x cannot be run in NumPy 2.x`） |
| 2.x 近期版本 | numpy 2.x 没问题 |

装完先自检一下，四条都不能报错：

```bash
python -c "import cv2, numpy, torch, ultralytics; print(ultralytics.__version__, numpy.__version__, torch.__version__, cv2.__version__)"
```

## 2. 图怎么摆

**一个车身一个文件夹，原图直接放在车身文件夹下**，不要再套子目录：

```
我的车身图/
├── PINC6202673911620_8X/
│   ├── 04__xxx.bmp
│   ├── 05__xxx.bmp
│   └── ...
└── PINC6202674000644_8X/
    └── ...
```

默认只认 `.bmp`。如果你的是 png/jpg，见下面第 5 节的注意事项——**别直接加扩展名**。

## 3. 跑

```bash
python run_batch_detect.py 我的车身图
```

它会为每个车身生成一个 `<车身名>_<时间戳>/` 文件夹，放在该车身文件夹里面。**不覆盖任何已有文件**——
每次跑都是新的时间戳夹，所以你可以放心地反复跑。

想先看它打算做什么、不写文件：

```bash
python run_batch_detect.py 我的车身图 --dry-run
```

不想让结果混进图片目录，就指定输出位置：

```bash
python run_batch_detect.py 我的车身图 --out-root D:/结果
```

跑完想把它整理成"红框图 / 轮廓图"两个子夹（我们的交付格式）：

```bash
python split_batch_folders.py 我的车身图 <上一步打印的时间戳>
```

## 4. 输出是什么

每个时间戳夹里三样东西。**两种图看的东西不一样，别搞混**：

**`<图名>_检测框_<时间戳>.png`** —— 只有红框。
红框是**算法拿去分析的窗口**（不是模型原始的预测框，窗口边上留了一圈余量）。
用来回答"它到底把哪儿圈进去算了"。

**`<图名>_胶条标注_<时间戳>.png`** —— 三种颜色叠在一起，这张是主要的：

| 颜色 | 线宽 | 是什么 |
|---|---|---|
| 红 | 2px | 分析窗口（跟上面那张红框同一位置） |
| 蓝 | 1px | 精修之后，胶条主体的**外接矩形** |
| 黄 | 1px | 精修之后的**胶条轮廓**（通常两根竖直的边，标出上下边界） |

黄线是我们认为胶条真正的上下边缘在哪。**你要看的边界就是它。**

**`胶条分割报告_<时间戳>.json`** —— 逐张图的数据，每张图一条记录：

| 字段 | 含义 |
|---|---|
| `file` | 原图文件名 |
| `det_boxes_raw` | 模型原始预测框（没加余量的），`[x0, y0, x1, y1]` 浮点坐标 |
| `rois` | 实际拿去分析的窗口，`[x, y, w, h]` |
| `strips[]` | 每个窗口的分割结果，见下 |

`strips[]` 里每一项：

| 字段 | 含义 |
|---|---|
| `red_box` | 对应的窗口 |
| `status` | `已分割` 或 `未分割到深色胶条` |
| `area` | 胶条像素数 |
| `bbox` | 胶条外接矩形（相对窗口左上角） |
| `median_thickness_px` | **胶条中位厚度（像素）**——要量化"胶条多粗"就看这个 |
| `thickness_std_px` | 厚度标准差，反映厚度是否均匀 |
| `refine_notes` | 算法给出的说明，例如"某侧端头候选覆盖不足，该侧不收缩" |

## 5. 注意事项（重要）

**① 图必须是同一台相机拍的。** 模型是在**宽 1920、高约 960 的横幅灰度图**上训练的。
换分辨率、换相机、换拍摄距离都可能让框变宽或变偏——不是模型坏了，是它没见过这种图。

**② 它假设胶条比背景暗。** 整个算法建立在"胶条是深色、背景是浅色"上。反光、强光斑、
白色密封胶覆盖在胶条上，都可能让那一段的边界画歪。

**③ 别把 png 加进 `--ext`。** 车身文件夹里常常同时躺着各种分析产物
（`*_胶条标注_*.png`、`*_已标注.png` 等）。`--ext` 是"扫描输入图"的扩展名，
加上 png 就会**把这些产物当成待检测的原图**扫进去，画出一堆莫名其妙的框，
而且**不报错**。要处理 png/jpg 原图，先把原图单独拷到一个干净目录里再跑。

**④ 端头（胶条的两头）本身就是难点。** 报告里的 `refine_notes` 说某侧"不收缩"是正常的——
胶条尽头之后画面里还有别的暗色东西时，算法会选择保守不猜。看端头边界时请自己复核一下。

**⑤ 跑出来的框不等于"缺陷判定"。** 这个包只做**定位和测量**（胶条在哪、多粗、边界在哪）。
喷涂质量好不好要另做判断，不在这个包里。

## 6. 结果不对怎么反馈

把这几样发回来，比描述有用得多：

1. 出问题的**原图**（bmp 原件）
2. 对应的**两张输出图**（`_胶条标注_` 和 `_检测框_`）
3. 那份 `胶条分割报告_*.json`
4. 一句"哪里不对"——比如"第 5 张的右端多画了一截"、"整条黄线都偏上了"

## 附：文件清单

| 文件 | 作用 |
|---|---|
| `run_batch_detect.py` | **入口**，跑这个 |
| `split_batch_folders.py` | 把结果分成红框图/轮廓图两个子夹 |
| `detect_gad_strips.py` | 检测器：出框。**别单独运行它**，它自带的自检要读我们仓库里的数据，在你机器上跑不起来 |
| `crop_and_segment.py` | 轮廓精修算法 |
| `segment_gad_20260909.py` | 画图 |
| `weights/gad_yolo11n.pt` | 模型权重。**这个路径不要改**，改了脚本就找不到它 |

`run_batch_detect.py --help` 看全部参数。
